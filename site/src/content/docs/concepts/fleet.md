A **fleet** is a git repository holding `servers/`, one folder per server, and
a `package.json` that pins the kayra version it runs. kayra knows no fleet by
name: it finds the fleet from the working directory (the nearest directory
with `servers/defaults.yml`) and validates every server whenever it loads it
— a broken `server.yml` anywhere stops every command.

The operating model is **one server per customer** (occasionally several apps on one server to save money), plus special-purpose servers. Everything about a server lives in its folder of the fleet; kayra holds only reusable code.

```
servers/shop-prod/
├── server.yml          topology only: kind, target, domain, apps
├── vars.yml            settings, plaintext (only what differs per server)
├── secrets.yml         every secret of the server, SOPS-encrypted (plaintext test values on multipass):
│                         the host's, each app's under app_secrets, OpenTofu's under terraform
├── apps/<app>.yml      the operator's config for each app, plaintext
├── terraform/          main.tf etc.; the state committed, encrypted
└── inventory.ini       generated by `kayra provision` (gitignored)
```

```yaml
# server.yml
kind: platform             # platform (Traefik, Authelia, the deployer, apps) | edge | nas
target: hetzner            # hetzner | multipass | home — gates cert source + /etc/hosts
domain: shop.example.com
age_key_file: ~/.config/sops/age/shop.txt   # optional: else SOPS's own default
apps:
  - {name: shop, repo: https://github.com/example/shop.git, ref: main, path: .}
```

- **OpenTofu state is committed, encrypted** *(checked: `run.sh --fleet` refuses a `terraform.tfstate` that is not)*: OpenTofu's state encryption (`terraform { encryption { … } }` with a pbkdf2 key from `var.state_passphrase`, AES-GCM), so the state is versioned and in every clone, and only who can open `secrets.yml` reads it. Commit the state after every `provision`/`down`.
- **Adding a customer** = copying a server folder, adjusting `server.yml`, `vars.yml`, `secrets.yml`, `apps/*` and `terraform/`.
- **Where a value goes** — by how much it varies, not by habit:
  - the same on every server (acme email, admin user, platform repo) → `servers/defaults.yml`, once
  - different per server, not secret → `vars.yml`, plaintext, so it can be read and diffed
  - secret → `secrets.yml`; kayra refuses a hetzner or home server whose `secrets.yml` is not SOPS-encrypted, and any whose `vars.yml` is. The same split per app: `apps/<app>.yml` (config, never encrypted) and `app_secrets.<app>` in `secrets.yml`
  - an OpenTofu variable that is secret (a Hetzner token, a password) → `terraform:` in `secrets.yml`, reaching OpenTofu as `TF_VAR_*`; one that is not → a committed `terraform/terraform.tfvars`
  - which repos a server's Renovate keeps up to date → `renovate_repositories` in its `vars.yml`
  - a value that never varies is not a setting: write it where it is used
- `kind` picks the playbook (`ansible/playbooks/<kind>.yml` in kayra); only `platform` servers run apps.
  `edge` (e.g. `servers/edge/`) is a WireGuard tunnel into a private network plus Caddy in front of it — roles `wireguard` + `edge-proxy`, routes and keys in its `vars.yml` — and the outside eye on that network's backups (`backup-check`: hourly, reads each repository's newest snapshot and restore-test result over read-only HTTPS, an alert to the `notifier` when either goes stale or a test fails) and, with `ntfy` set, an ntfy server for the fleet's alerts (role `ntfy`: users, access and tokens as code, everything else denied; Caddy reaches it through an `edge_routes` entry to `ntfy:80`).
  `nas` (`servers/nas/`) is a box whose OS belongs to its vendor (UGOS): the play writes nothing outside `nas_root` (`/volume2`) and asserts so before any change — no packages, users or system config, which a firmware update would reset; everything runs as containers. `/volume1` (media, homes) is never written; the backup reads from it (`restic_backup.paths`, mounted read-only, asserted to exist so Docker never creates one). Role `compose-stacks`: the services, one `servers/nas/stacks/<name>/compose.yaml` each, every image pinned, only what differs from the image's defaults plus an explicit `container_name` (the proxy's Caddyfile addresses containers by it) — the stack folder (compose file plus any config it mounts as `./…`, e.g. Homepage's dashboard, read-only) and an `.env` to `/volume2/docker/stacks/<name>/`, data mounted from where it already lives. Private images: `compose_registry_logins` in `secrets.yml` (`{registry, username, password}`), logged in with a Docker config inside the stacks' directory, never the host's. Role `restic-backup`: nightly restic over SFTP to a Hetzner Storage Box (`servers/nas/terraform/`, its own daily snapshots), Postgres dumped first, pruned on Sundays; a restore test monthly by cron (a twelfth of the data read each time) and by hand with `kayra backup test nas`, its result uploaded next to the repository.
- `target: home` is a machine at home that nothing can create for us: no `terraform/`, a hand-written, committed `inventory.ini`, and otherwise treated like hetzner — SOPS required, changed only from `main`. A NAS is one; a VM on it another: for those, `kayra provision` builds the Ubuntu cloud image and a seed ISO from the same `cloud-init.yml.tpl` (plus a fixed address, `vm:` in `vars.yml`), imported into UGOS's VM app by hand.
- **Adopting a server we did not create** (it keeps its IP/type/price): `import {}` it into its `terraform/`, rebuild it from the Hetzner console/API, `kayra adopt <name>` (creates `deploy` as root, once), then `kayra deploy <name>`. `hcloud-server` ignores `user_data`/`ssh_keys`/`image` for exactly this — and so that a cloud-init edit never replaces a live server.
- **Testing platform changes before merging:** `npm link @yunuseon/kayra` to the branch's checkout in the fleet, and `ref: <branch>` on the app entry, against a multipass server. Only a multipass server ever runs anything but a release: `require-main.sh` refuses a hetzner or home server while the fleet's kayra is a linked checkout.
- **Hetzner servers only change from `main` as merged, with a released kayra.** Every kayra command deploys the local checkout; `require-main.sh` makes `provision`, `adopt`, `setup`, `apps` and `app purge` refuse a hetzner or home server unless the fleet's checkout is a clean `main` equal to `origin/main` (other servers' folders may be dirty — that is where test pointers live) and its kayra is the pinned package, not a link. A secrets edit for prod therefore goes through a PR before it is deployed. Never add a bypass: deploying a feature branch to prod once turned the platform's own checks off there.
- **An app in its own repo** needs, once: the platform's `git_token` extended to the repo (clone, commit statuses) and the Renovate token if Renovate keeps it current, a push webhook to `https://deploy.<domain>/hook/<app>` signed with the platform's `webhook_secret` (a Forgejo on the same server: `http://builder:8080/hook/<app>`, set by `forgejo-config`), and `kayra apps <server>`. The hourly poll deploys a moved ref even without the webhook. The app's local dev never needs the platform.

## Secrets

`secrets.yml` is [SOPS](https://getsops.io): each value encrypted, the keys in
plaintext. So a pull request shows which secret changed, and `kayra validate`
checks every key, and each value's type, without being able to read one (the
fleet's CI holds no key). One file per server, so a run opens one file:

```yaml
git_token: ENC[AES256_GCM,data:…,type:str]
app_secrets:
    shop:
        DATABASE_PASSWORD: ENC[AES256_GCM,data:…,type:str]
terraform:
    hcloud_token: ENC[AES256_GCM,data:…,type:str]
    state_passphrase: ENC[AES256_GCM,data:…,type:str]
sops:
    age:
        - recipient: age1se1…   # the operator's Secure Enclave key
        - recipient: age1…      # the offline backup key
```

- **Whom it is encrypted to** is `.sops.yaml` at the fleet's root: a
  `creation_rules` entry whose `path_regex` matches the file, and its age
  recipients. `kayra validate` refuses a `secrets.yml` encrypted to anyone else
  than its rule names; after a change to the rule, `sops updatekeys` the file —
  and rotate what a removed key could read, since git keeps the old ciphertext.
- **Keys, by who uses them:** the operator's (an age identity; with
  [age-plugin-se](https://github.com/remko/age-plugin-se) a key in the Mac's
  Secure Enclave, which never leaves it, and asks for Touch ID if made with
  `--access-control=any-biometry-or-passcode`); an offline backup key on every
  file, its private half only in a password manager — the Enclave's key dies
  with the Mac; and, for runs nobody watches, a key of their own where they run,
  never one that opens without asking in the operator's session. `age_key_file`
  in `server.yml` names the identity; without it, SOPS's own default
  (`SOPS_AGE_KEY_FILE`, `~/.config/sops/age/keys.txt`).
- **kayra opens it once per run**, on the first step that needs it (one Touch
  ID): for Ansible a plaintext copy in the run's private directory, removed
  when the run ends, named by `KAYRA_SECRETS`; for OpenTofu the `terraform`
  mapping as `TF_VAR_*`. Steps that need no secret open nothing: `kayra app
  values`, `kayra validate` and the value checks of `kayra app launch` read the
  keys only.
- **Changing a value:** `kayra app secret generate|import` sets one app secret
  with `sops set`, every other value's ciphertext left as it was; anything else
  `sops edit servers/<server>/secrets.yml`. Two branches that change the same
  file conflict on its `sops` metadata: decrypt both sides, merge, encrypt again.

## DNS

A platform server's records follow from the fleet, never from a list kept by
hand: kayra's `platform-dns` module (OpenTofu, Hetzner DNS) makes an A record
for each of the platform's own subdomains and for every route host of every
app in its `server.yml`, as the app's `app.yml` in the fleet's clone
(`.cache/apps`, which `kayra doctor` fills) says.

```hcl
# dns/terraform/main.tf in the fleet, in a Hetzner project of its own
module "shop_prod" {
  source     = "../../node_modules/@yunuseon/kayra/terraform/modules/platform-dns"
  fleet_root = "${path.module}/../.."
  server     = "shop-prod"
  zone       = hcloud_zone.this.name
  address    = data.terraform_remote_state.shop_prod.outputs.server_ip
}
```

A new route host in an app is a new record on the next `tofu apply` in
`dns/terraform`; an app the fleet has not cloned stops the plan with a pointer
to `kayra doctor` rather than leaving its hosts out. A server whose domain is
under the zone (`shop.example.com` in `example.com`) gets `www.shop`, and so on.
