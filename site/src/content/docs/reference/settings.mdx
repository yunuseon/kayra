A server's `vars.yml` may set the settings of its kind and nothing else: an unknown key stops every
kayra command, with a suggestion where it looks like a typo. `servers/defaults.yml` holds settings
shared by every server. Secrets go in `secrets.yml` — a secret in `vars.yml` is refused.

Editors complete and check these files from the JSON Schemas in the package (`schema/`), e.g. as
the first line of a platform server's `vars.yml`:

```yaml
# yaml-language-server: $schema=../../node_modules/@yunuseon/kayra/schema/vars-platform.json
```

## Settings

| Setting | Kinds | What it is |
|---|---|---|
| `acme_email` | platform, edge | The Let's Encrypt account contact: expiry warnings land here. |
| `docker_version` | platform, edge | The Docker CE major the docker role pins and holds, as an apt version glob (default 5:29*). |
| `authelia_policy` | platform | What Authelia asks of staff: two_factor (default) or one_factor. |
| `authelia_smtp_address` | platform | SMTP server for Authelia's mails (passkey enrolment); empty: mails go to a file. |
| `authelia_smtp_username` | platform | SMTP user for Authelia. |
| `authelia_smtp_sender` | platform | Sender address of Authelia's mails. |
| `acme_dns` | platform | Certificates by DNS-01 instead of HTTP-01, for a server the internet never reaches: the DNS provider (hetzner). |
| `webhooks` | platform | Whether a push webhook may start a deploy at once: true (default) serves deploy.&lt;domain>/hook/&lt;app>; false serves no such endpoint, and pushes deploy by deploy_poll. |
| `deploy_poll` | platform | When the deployer looks for pushes no webhook brought, as a five-field cron spec in the server's time (default hourly: 17 * * * *). |
| `renovate_repositories` | platform | owner/repo of the repos this server's Renovate job keeps up to date; the job runs only where the list is not empty. |
| `renovate_schedule` | platform | When the Renovate job runs, as a five-field cron spec in the server's time (default weekly: 0 4 * * 1). |
| `renovate_platform` | platform | Where the repos live: github (default), forgejo or gitlab. |
| `renovate_endpoint` | platform | With a Forgejo: its API on platform-internal, e.g. http://forgejo:3000/api/v1. |
| `renovate_git_url` | platform | How Renovate clones; endpoint with a Forgejo, so it uses the internal address. |
| `renovate_host_rules` | platform | Renovate hostRules: allowInternal for a Forgejo on platform-internal, credentials for a private registry. |
| `vm` | platform | target home: the VM kayra provision builds — fixed address (CIDR), gateway, disk size. |
| `forgejo_config` | platform | What this server's own Forgejo holds, as code: users, SSH keys, organizations, runners, repos (settings, collaborators, webhooks, mirrors) and the tokens it mints for the platform. |
| `compose_stacks` | platform, nas | The server's own compose stacks: their directory on the server and the names under stacks/ to run. |
| `nas_root` | nas | The only directory the NAS play writes in, asserted before any change (e.g. /volume2). |
| `restic_backup` | nas | The nightly restic backup: what, where to (SFTP), when, how long kept, and the monthly restore test. |
| `wireguard` | edge | The tunnel into the private network: the edge's address, port, and the one peer (its key, what it may reach). |
| `edge_routes` | edge | Public names the edge serves: subdomains of the domain and the upstream inside the tunnel they go to. |
| `ntfy` | edge | An ntfy server for alerts, behind Caddy (an edge_routes entry to ntfy:80): its public base_url, who may read or publish which topic (everything else denied), and upstream_base_url (https://ntfy.sh) for iPhones, whose instant push only ntfy.sh can wake. |
| `monitor` | platform, edge | Gatus on this server, alerting through the notifier: every minute, what kayra derives for each server in watch (its logins, pages, app routes, deploy.&lt;domain>/health; an edge's routes; certificates) with each name pinned to that server's address, plus extra checks (Gatus conditions, default [STATUS] == 200; server pins the name to that server's address). |
| `notifier` | platform, edge | Where alerts go — the deployer's (a failed deploy of an app's ref, a failed job) and the backup check's: kind ntfy, a message to topic on the ntfy server at url when an alert opens and when it is resolved; the token in notifier_ntfy_token. |
| `backup_check` | edge | The hourly check of the private network's backups: when a snapshot is stale, which repositories. Its alerts go to the notifier. |

## Secrets

| Setting | Kinds | What it is |
|---|---|---|
| `notifier_ntfy_token` | platform, edge | With notifier kind ntfy: the access token alerts are published with. |
| `git_token` | platform | Token the builder clones app repos with and the deployer posts commit statuses with. |
| `health_token` | platform | Bearer token a monitor reads deploy.&lt;domain>/health with: the platform's and every app's containers, the disk and memory. Unset, there is no such page. |
| `webhook_secret` | platform | HMAC secret the apps' push webhooks (deploy.&lt;domain>/hook/&lt;app>) are signed with. |
| `renovate_token` | platform | Token the Renovate job opens PRs with. |
| `renovate_github_com_token` | platform | Public-read GitHub token for Renovate's lookups off GitHub. |
| `authelia_session_secret` | platform | Authelia's session secret. |
| `authelia_storage_encryption_key` | platform | Authelia's storage encryption key. |
| `authelia_smtp_password` | platform | Authelia's SMTP password. |
| `authelia_users` | platform | Staff accounts: name, email, argon2id password hash. |
| `acme_dns_token` | platform | With acme_dns: the DNS provider's token, for DNS-01 only. |
| `forgejo_admin_token` | platform | forgejo-config's token: admin, organization, repository, user (read and write). |
| `forgejo_runner_secrets` | platform | Per runner name: the 40-character secret shared by the runner and Forgejo. |
| `forgejo_action_secrets` | platform | Actions secrets per repo. |
| `forgejo_push_mirror_credentials` | platform | The account push mirrors push with. |
| `compose_stack_secrets` | platform, nas | Per stack: the variables of its .env. |
| `compose_registry_logins` | platform, nas | Private registries the stacks pull from. |
| `restic_backup_password` | nas | The restic repository's password. |
| `restic_backup_ssh_key` | nas | The SSH key the backup reaches the Storage Box with. |
| `restic_backup_postgres_passwords` | nas | Per database container: the password its dump connects with. |
| `ntfy_password_hashes` | edge | Per ntfy user: the bcrypt hash of its password (ntfy user hash). |
| `ntfy_tokens` | edge | Per ntfy user: an access token (ntfy token generate), e.g. the one monitors publish with. |
| `monitor_health_tokens` | platform, edge | Per watched platform server: its health_token, which the monitor reads deploy.&lt;domain>/health with. |
| `wireguard_private_key` | edge | The edge's WireGuard private key. |
| `wireguard_peer_psk` | edge | The tunnel's preshared key. |
| `backup_check_passwords` | edge | Per watched repository: its read-only password. |

Ansible's own variables (`ansible_*`) are allowed everywhere.
